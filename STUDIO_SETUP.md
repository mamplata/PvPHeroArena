# Roblox Studio Setup and Run Guide

This guide explains how to open, sync, test, and save `PvPHeroArena`.

## 1. Project location

The project is located at:

```text
/home/nana7/Roblox/PvPHeroArena
```

The source files are the source of truth. Edit the `.lua` and `.json` files in this folder, then let Rojo sync them into Studio.

## 2. Required tools

You need:

- Roblox Studio.
- The Rojo Studio plugin.
- Rojo command-line tool.
- This project folder.

Rojo is already installed in this workspace. If the command is unavailable in your terminal, use:

```bash
/home/nana7/.rokit/bin/rojo
```

## 3. Start the Rojo server

Open a terminal and run:

```bash
cd /home/nana7/Roblox/PvPHeroArena
rojo serve default.project.json
```

Keep this terminal open while working. Rojo watches the source files and serves changes to Studio.

## 4. Connect Roblox Studio

1. Open Roblox Studio.
2. Create a new Baseplate or open a local place.
3. Open the **Rojo** plugin.
4. Connect to the local Rojo server, normally on port `34872`.
5. Confirm that the project tree appears in Explorer.

After connecting, the project scripts should appear under:

```text
ReplicatedStorage
ServerScriptService
StarterPlayer
```

The arena is generated by `ArenaBootstrap` when Play starts, so it may not appear in edit mode.

## 5. Start the game

Press **Play** in Studio.

The server generates:

- Citadel Courtyard.
- Lobby floor and lobby spawn.
- Arena spawn points.
- Walls, cover, center platform, and boundaries.
- RemoteEvents and match state.

Check the Output window for:

```text
Citadel Courtyard loaded
Hero combat server ready
Match server ready
Arena boundary service ready
Runtime log collector ready
```

## 6. Test with two players

Use **Test → Start** and choose two players.

The first two players become the active match. Extra players stay in the lobby.

### Controls

- `1` — select Knight while in the lobby.
- `2` — select Mage while in the lobby.
- `3` — select Rogue while in the lobby.
- Left click — basic attack.
- `Q` — Knight shield block.
- `E` — first skill.
- `R` — second skill.

The match runs best-of-three. Players respawn between rounds and return to the lobby after the match.

## 7. Run the automated smoke test

Start Play first, then open the Studio Command Bar:

1. Open the **View** tab.
2. Click **Command Bar**.
3. Use the **Server** context if Studio shows a context selector.
4. Run:

```lua
workspace:SetAttribute("RunMVPTests", true)
```

Read the Output window. A healthy run ends with:

```text
[MVP RESULT] PASS - smoke checks completed
```

The runner is safe to leave enabled in the project. It does nothing until the attribute is set to `true`.

## 8. Inspect runtime logs

While Play is running, logs are stored in:

```text
ServerStorage.RuntimeLogs
```

To print the captured logs, run this in the server Command Bar:

```lua
for _, entry in ipairs(game:GetService("ServerStorage").RuntimeLogs:GetChildren()) do
    print(entry.Value)
end
```

The buffer keeps the newest 250 entries and is cleared when the server restarts.

## 9. Make a code change

1. Edit a source file in `/home/nana7/Roblox/PvPHeroArena`.
2. Save the file.
3. Wait for Rojo to sync.
4. Stop and restart Play when the change affects server startup or generated objects.

Examples:

- Combat values: `src/ReplicatedStorage/Shared/CombatConfig.lua`.
- Arena layout: `src/ServerScriptService/ArenaBootstrap.server.lua`.
- Combat validation: `src/ServerScriptService/CombatServer.server.lua`.
- Match flow: `src/ServerScriptService/MatchServer.server.lua`.
- HUD: `src/StarterPlayer/StarterPlayerScripts/CombatHUD.client.lua`.

Do not edit Rojo-managed scripts directly in Studio. Edit the source files and let Rojo sync them.

## 10. Build a local place file

To create a local `.rbxlx` file:

```bash
cd /home/nana7/Roblox/PvPHeroArena
rojo build default.project.json -o PvPHeroArena.rbxlx
```

Open the generated file in Studio with **File → Open from File**.

The generated arena still appears at runtime because the server script creates it when Play starts.

## 11. Save or publish the game

### Save locally

Use **File → Save to File** if you want a local Studio place copy.

### Publish online

While Rojo is connected:

1. Use **File → Publish to Roblox As...**.
2. Choose **Create New** or select an existing experience.
3. Publish the place.

Keep the Rojo source folder as the code source. Publishing Studio does not replace the need to save source-file changes.

## 12. Stop the project

1. Stop Play in Studio.
2. Stop Rojo in the terminal with `Ctrl+C`.

## 13. Troubleshooting

### Rojo command not found

Run the full path:

```bash
/home/nana7/.rokit/bin/rojo serve default.project.json
```

### Rojo plugin cannot connect

- Confirm the terminal is still running `rojo serve`.
- Confirm Studio is connecting to the local server.
- Restart the Rojo plugin and reconnect.
- Make sure another Rojo server is not using the same port.

### Scripts do not appear

- Confirm the plugin is connected to `PvPHeroArena`.
- Confirm the terminal working directory is `/home/nana7/Roblox/PvPHeroArena`.
- Check `default.project.json` for mapping errors.
- Reconnect Rojo after changing the project tree.

### Arena does not appear

- Press **Play**, not only **Run** in edit mode.
- Check the Output window for server errors.
- Run the MVP smoke test.

### No match starts

- Start with at least two players using **Test → Start**.
- Check that the HUD says `WAITING FOR 2 PLAYERS` or shows the countdown.
- Check `ServerStorage.RuntimeLogs` for errors.

### Changes are not visible

- Save the source file.
- Wait for the Rojo sync message.
- Stop and restart Play for server-generated objects.
- Do not rely on changes made directly to Rojo-managed scripts in Studio.
